# Maths League — Supabase build

Maths League is a student maths-competition platform with registration, authentication, daily quizzes, server-side scoring, progress tracking, leaderboard rankings, announcements, and an admin dashboard.

## Current architecture

The web application now uses **Supabase** for:
- Authentication
- PostgreSQL student/profile data
- Quiz configuration and questions
- Immutable quiz attempts
- Leaderboard calculations
- Announcements
- Admin authorization with Row Level Security

Firebase remains in the repository as a **rollback/deployment fallback only**. The frontend no longer imports the Firebase client SDK.

## Security model

- Student profile rows are protected by Row Level Security.
- Students cannot directly change points, quiz totals, or attempt scores.
- Quiz questions containing correct answers are not readable directly by students; `get_daily_quiz()` returns only public question data.
- Quiz scoring is performed inside the trusted `submit_daily_quiz()` database function.
- A unique `(student_id, quiz_id)` constraint prevents duplicate daily submissions.
- Admin operations require membership in `admin_users`.
- Registration numbers are generated by the authentication trigger.

## Supabase project

The production project is configured through `js/supabase.js` using the publishable browser key. Never put a Supabase service-role key in frontend code.

The database migrations create:

- `students` — student profiles and aggregate statistics
- `quiz_configs` — daily quiz configuration
- `quiz_questions` — quiz questions and trusted answers
- `quiz_attempts` — submitted results
- `announcements` — published notices
- `admin_users` — administrator authorization

## Development

The frontend is plain HTML/CSS/JavaScript and loads Supabase JS from the browser. No frontend build step is required.

Run the JavaScript syntax/legacy smoke checks with the repository GitHub Actions workflow.

## Firebase fallback

The old Firebase configuration and Cloud Functions are intentionally retained during the migration so the live Firebase deployment can remain a fallback while the Supabase version is verified. Do not delete the Firebase project until the Supabase application has been tested end-to-end.

## Repository name

The repository is intentionally still named `Maths-leauge` to avoid breaking existing links or deployment references.
